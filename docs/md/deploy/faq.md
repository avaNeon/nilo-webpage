# 常见问题

本文记录 Nilo 前端构建与发布过程中遇到的问题及处理方法

## CI 与构建

| 现象                                                                                                         | 原因                                                                                                                                                  | 处理                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| CI 的 `npm ci` 报 `package.json and package-lock.json are not in sync`，或提示 `Missing: xxx from lock file` | 锁文件在某个操作系统上生成，缺少其他系统才会安装的可选依赖（例如在 Windows 上生成的锁文件缺少 Linux 需要的项）。本地安装不报错，只有换到 Linux 才暴露 | 把报错中缺失的包显式添加为 `devDependencies` 并重新生成锁文件。提交前可在本地模拟 Linux 检查：`npx npm ci --dry-run --os=linux --cpu=x64 --libc=glibc` |
| 本地构建通过，CI 报 `TS1261`，提示文件名大小写不一致                                                         | Windows 与 macOS 的文件系统不区分大小写，Linux 区分。git 中记录的文件名与 `import` 的写法大小写不同，本地感知不到                                     | 统一文件名与引用的大小写。在不区分大小写的系统上改名需要分两步（先改为临时名，再改为目标名），否则 git 不会记录这次改名                                |
| 本地构建通过，CI 报找不到某个图片、字体或样式文件                                                            | 该文件被 `.gitignore` 忽略，只存在于本地                                                                                                              | 被代码引用的素材必须纳入版本库；只想留作备份的素材放进被忽略的备份目录。通过目录批量引用的素材缺失时构建不会报错，只会在页面上缺图，需要留意           |

## 发布

| 现象                                                                         | 原因                                                                                                      | 处理                                                                                                  |
| ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 推送到 main 后，CI 在校验步骤失败，提示没有配置 `MINIO_ENDPOINT`             | 必填的仓库变量未配置                                                                                      | 在仓库的 Variables 中添加，见 [config.md](config.md)，然后重新运行这次 CI                             |
| 发布在获取产物步骤失败，提示没有构建成功的 CI                                | CI 还没跑完或失败了；触发发布时选择的不是 main 上的提交                                                   | 等 CI 成功后重新触发，并选择 main 分支                                                                |
| 发布在校验步骤失败，提示一个前端都没勾选                                     | 触发时两个选项都没有勾选                                                                                  | 至少勾选一个前端后重新触发                                                                            |
| 上传步骤报 `Permission denied (publickey)`                                   | 私钥与服务器上登记的公钥不匹配；私钥设置了口令（CI 中无法输入口令）；`authorized_keys` 中的公钥粘贴不完整 | 使用不带口令的专用密钥；核对服务器上登记的公钥是整整一行；检查 `.ssh` 目录与 `authorized_keys` 的权限 |
| 用上传账户的私钥手动执行命令，提示 `SSH_ORIGINAL_COMMAND does not run rsync` | **这是预期的防护**，该密钥只能用于 rsync，见 [security.md](security.md)                                   | 无需处理                                                                                              |
| 冒烟检查失败                                                                 | 主站不可访问，或返回的不是前端页面（例如证书、nginx 站点配置有问题，请求落到了默认站点）                  | 在本机用 `curl` 访问主站，对照返回内容排查 nginx 配置                                                 |

## 访问

| 现象                                                   | 原因                                                                         | 处理                                                                        |
| ------------------------------------------------------ | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 直接打开或刷新 `/video/xxx` 这类地址返回 404           | 这类地址只在前端路由中存在，服务器上没有对应文件。nginx 未配置单页应用回退   | 配置"找不到文件时返回 `index.html`"，见后端仓库的 `docs/md/deploy/nginx.md` |
| 发布后，已经打开着的页面点击跳转时白屏或报加载脚本失败 | 发布时旧版本的文件被删除，而旧页面还在请求它们。这是单页应用发布时的常见现象 | 刷新页面即可。`index.html` 不缓存，刷新后拿到的就是新版本                   |
| 发布成功后，图片与视频加载失败                         | 构建时注入的对象存储地址不正确。该值被写进了 JS，之后无法更改                | 修正仓库变量 `MINIO_ENDPOINT` 后，**重新运行 CI 构建，再重新发布**（发布使用已构建好的产物，只改变量不会生效）                                |
