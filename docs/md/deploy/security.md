# 部署安全

本文说明 Nilo 前端发布涉及的权限控制

> 注意：文中的 **GitHub 云服务器**指 GitHub Actions 执行任务时临时分配的运行环境；**服务器**指运行 Nilo 的机器

## 目标

发布时，GitHub 云服务器需要把构建产物上传到服务器，因此必须提供上传账户的 SSH 私钥。

目标是遵循最小权限原则：即使私钥泄露，攻击者也只能向网站目录写入文件，无法登录服务器、执行命令或读取服务器上的其他内容。

## 权限限制

上传使用专用账户，并通过四层机制限制其权限：

| 层                | 机制                                                            | 限制内容                                                        |
| ----------------- | --------------------------------------------------------------- | --------------------------------------------------------------- |
| 1. 专用账户与密钥 | 独立的上传账户，公钥认证，私钥仅存放于 GitHub Secrets           | 与后端部署账户、日常登录的账户和密钥完全分离，互不影响          |
| 2. SSH 强制命令   | 公钥在 `~/.ssh/authorized_keys` 中绑定 `command=` 与 `restrict` | 该密钥登录后只能运行 `rrsync`；禁用交互终端、端口转发、代理转发 |
| 3. rrsync         | rsync 自带的受限包装程序，以只写模式运行，并锁定目录            | 只允许向网站根目录写入；不允许读取，不允许访问该目录以外的路径  |
| 4. 目录权限       | 网站根目录归该账户所有，该账户没有 sudo 权限                    | 除网站根目录外没有写权限，也无法提升权限                        |

### rrsync

`rsync` 通过 SSH 传输文件：客户端登录后，在服务器上启动一个 `rsync` 进程来接收文件。`rrsync`（restricted rsync）是 rsync 自带的限制程序，上传账户的 SSH 强制命令指定了它，因此该密钥发起的任何连接，服务器都只会交给 `rrsync` 处理：

| 客户端发来的请求            | 结果                  |
| --------------------------- | --------------------- |
| 用 rsync 向站点目录上传文件 | 执行                  |
| 用 rsync 从服务器读取文件   | 拒绝：只允许写入      |
| 目标路径超出网站根目录      | 拒绝：路径被锁定      |
| 其他命令，例如 `ls /`       | 拒绝：不是 rsync 命令 |

验证方式：用该私钥执行一条普通命令，应被拒绝并提示 `SSH_ORIGINAL_COMMAND does not run rsync`。

## 私钥泄露的影响

| 能做                           | 不能做                         |
| ------------------------------ | ------------------------------ |
| 向网站目录上传、覆盖、删除文件 | 获得终端、执行任意命令         |
|                                | 读取服务器上的任何文件         |
|                                | 写入网站根目录以外的位置       |
|                                | 接触后端的部署账户、容器与数据 |

残余风险：攻击者可以替换网站文件，例如植入恶意脚本。这是静态托管方式本身无法避免的，处理方式是发现泄露后立即在服务器上删除对应公钥，并重新生成密钥对。

## 进入前端的信息

前端产物是公开的，任何访问者都可以下载。因此只有 `VITE_` 开头的公开信息会进入构建，密钥不能放进前端，详见 [config.md](config.md)。

## 后台站点的访问限制

后台管理站仅允许指定来源 IP 访问，其余请求由 nginx 拒绝，见后端仓库的 `docs/md/deploy/nginx.md`。

## 范围

- 权限限制针对上传账户，不涉及服务器本身的其他安全措施。
- 上传连接首次建立时信任服务器的主机公钥，没有预置指纹校验。认证基于公钥，私钥不会被发送给服务器；上传的内容本身就是公开产物，因此风险很小。
- 上传完成后不校验文件内容，只做冒烟检查（见 [cicd.md](cicd.md)）。
