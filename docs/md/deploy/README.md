## 应用

| 应用       | 目录         | 说明                   |
| ---------- | ------------ | ---------------------- |
| 用户端主站 | nilo-project | 面向所有用户           |
| 后台管理站 | nilo-admin   | 仅允许指定来源 IP 访问 |

## 整体结构

前端构建后是一组静态文件，服务器上**没有前端进程**，由 nginx 直接读取并返回：

```
浏览器 ── HTTPS ──▶ nginx ──▶ 静态文件（index.html、JS、CSS、图片）
```

页面加载后，前端代码在用户的浏览器中运行，并发出两类请求：

| 请求               | 去向                                              |
| ------------------ | ------------------------------------------------- |
| 业务接口（`/api`） | 发给 nginx，由 nginx 按路径前缀转发给对应的微服务 |
| 图片、视频等媒体   | 浏览器直接访问对象存储（MinIO），不经过微服务     |

因此：

- 发布前端就是替换服务器上的文件，无需重启任何进程，也不影响后端。
- 后端不可用时页面仍能打开，只是数据加载不出来。

## 发布流程

1. 代码提交后，GitHub 自动执行构建检查；推送到 main 时，还会保存构建产物（构建时注入环境相关的值）（CI）。
2. 通过 **GitHub Actions** **手动触发**发布，并勾选需要发布的前端。
3. GitHub 云服务器取出对应提交的产物，通过受限的 SSH 账户上传到服务器，随后自动执行冒烟检查。

详见 [cicd.md](cicd.md)。
