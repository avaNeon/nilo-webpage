# 构建配置

本文说明 Nilo 前端的环境相关配置如何注入，以及哪些内容可以进入前端

## 目标

- 环境相关的值（访问地址等）不写进源码，不提交到仓库。
- 前端产物是公开的，其中不能出现任何密钥。

## 前端配置的特点

前端与后端的配置方式不同。后端从 Nacos 在**运行时**读取配置；前端代码运行在用户的浏览器里，没有可以读取配置的地方，Vite 在**构建时**把以 `VITE_` 开头的变量替换为字面值写入 JS，之后无法更改。因此：

- 修改配置需要重新构建（重新运行 CI）并发布。
- 所有 `VITE_` 变量都会出现在公开的 JS 中，任何访问者都能看到。
- 不以 `VITE_` 开头的变量不会被打包。

## 配置项

| 变量                      | 作用                                      | 本地开发                             | CI 构建时                       |
| ------------------------- | ----------------------------------------- | ------------------------------------ | ------------------------------- |
| `VITE_APP_BASE_URL`       | 接口路径前缀，与 nginx 的转发前缀约定一致 | `/api`，由开发服务器代理到本机微服务 | 固定为 `/api`，写在 CI 工作流中 |
| `VITE_MINIO_ENDPOINT`     | 浏览器访问对象存储的地址，不带末尾斜杠    | 本地 MinIO 地址                      | 取自仓库变量 `MINIO_ENDPOINT`   |
| `VITE_MINIO_IMAGE_BUCKET` | 图片所在 bucket                           | 代码中有默认值                       | 不注入，使用代码中的默认值      |
| `VITE_MINIO_VIDEO_BUCKET` | 视频所在 bucket                           | 代码中有默认值                       | 不注入，使用代码中的默认值      |

## 注入方式

```
本地开发：.env（不提交） ──▶ vite dev
CI：      GitHub 仓库变量 ──▶ 工作流传入构建命令的环境变量 ──▶ vite build
```

- `.env` 已加入 `.gitignore`，不提交；仓库中不保留任何环境文件，构建所需的变量全部由 CI 工作流传入。
- Vite 中，进程的环境变量优先于 `.env` 文件。CI 的环境里本来就没有 `.env`。

## GitHub 仓库中的配置

在仓库 Settings → Secrets and variables → Actions 中配置：

| 类型      | 名称              | 内容                                                          |
| --------- | ----------------- | ------------------------------------------------------------- |
| Secrets   | `SSH_HOST`        | 服务器地址                                                    |
| Secrets   | `SSH_USER`        | 上传专用账户名                                                |
| Secrets   | `SSH_PRIVATE_KEY` | 该账户的专用私钥，账户的权限限制见 [security.md](security.md) |
| Variables | `MINIO_ENDPOINT`  | 浏览器访问对象存储的地址，推送到 main 时**必填**              |
| Variables | `SITE_URL`        | 主站地址，用于发布后的冒烟检查，可选，不填则跳过检查          |

Variables 不是机密，其中的值会被打包进公开的 JS，**不能放密钥**；Secrets 会被 GitHub 在日志中自动遮盖。

## 配置缺失的风险

`VITE_MINIO_ENDPOINT` 在代码中带有开发用的默认值。如果构建时没有注入，构建仍会成功，但页面中的图片与视频地址会指向开发环境，属于悄无声息的错误。

为此 CI 在推送到 main 且 `MINIO_ENDPOINT` 未配置时直接失败，而不是回退到默认值。`VITE_APP_BASE_URL` 是与 nginx 转发前缀之间的约定，由工作流固定传入。

## 新增配置项方式

| 配置的特点           | 放置位置                                                                                                 |
| -------------------- | -------------------------------------------------------------------------------------------------------- |
| 与环境无关           | 写在代码里，作为常量或默认值                                                                             |
| 随环境变化，可以公开 | 使用 `VITE_` 变量：本地写入 `.env`；在 CI 工作流的构建步骤中传入，值来自仓库变量；必填项在校验步骤中检查 |
| 属于密钥             | 不能放进前端。交给后端保存，由后端接口间接使用                                                           |

## 本地运行

在应用目录（`nilo-project` 或 `nilo-admin`）中：

```bash
npm ci
npm run dev
```

开发服务器会把 `/api/...` 请求代理到本机的微服务（见各应用的 `vite.config.ts`）。本地 `.env` 至少需要：

```
VITE_APP_BASE_URL=/api
VITE_MINIO_ENDPOINT=<本地 MinIO 地址>
```
